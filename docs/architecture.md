# 構成の理由

このリポジトリでは、**公開入口を固定し、機能ごとにコードと説明をまとめ、読み込み順を一か所で管理する構成**を採用しています。

## 機能ごとにまとめる

CSS だけの機能、JS だけの機能、両方が組になる機能があります。`src/features/<id>/` にまとめると、ある表示や操作を直すときに、関連コードと README を同じ場所から見つけられます。元ページ名は日本語の機能名・出典として残し、配信パスには英数字の ID を使用します。

処理を全機能共通の巨大な Script にまとめることはしていません。機能固有の状態・イベント・後片付けは、その機能内に置きます。共通化は、同じ振る舞いであることを確認できる処理から行います。

大きい機能の中では役割をさらに分けます。CSSはセル・ヘッダー・タイトルなどを別ファイルにし、`style.css` の相対importで順序を表します。配信用CSSは生成時に結合するので、分割による追加の読み込み階層はありません。空のスタイル規則を3件除き、セレクター・詳細度・宣言順・メディア条件を維持しています。

Scriptの `script.js` は初期化・状態・イベント・監視・後片付けを担当します。CSV解析、数式エンジン、リンクや記法の解析、DOM部品など、独立して扱える処理を補助モジュールへ分けています。機能ごとに異なる判定やライフサイクルを無理に共通化せず、各機能の外から状態を変更する仕組みも追加していません。

`types.js` はJSDocの型定義をまとめるファイルです。コメントから参照し、実行時には配信しません。`config/features.json` の `dataFiles`・`styleFiles`・`typeFiles`・`fileDescriptions` から、検証対象・配信対象・各READMEを生成します。

## 公開入口と実装を分ける

`style.css` と `script.js` は GitHub 上の配布入口です。以前の `src/Settings/style.css` と `src/kame/script.js` も、この入口へ転送する互換ファイルとして残しています。

実ブラウザの確認では、Scrapbox の CSP により外部 CDN の CSS・ES Modules はブロックされました。そのため Scrapbox 用には `dist/kame-layout.scrapbox.json` を生成し、同一オリジンの `/api/code/プロジェクト/kame-layout:delivery/` を入口にします。外部 URL の直接 import を前提にしません。CSP を無効化する設定や拡張機能も必要ありません。

JSON は配信用の1ページです。CSS・JS・補助モジュールは `fonts.style.css`、`templates.script.js` のように機能ID付きのコードブロック名へ対応させます。相対 import と `import.meta.url` を基準にする CSS の参照先だけを、この配置へ書き換えます。機能ごとのモジュール境界と実行順は維持します。既存の Settings・ユーザーページは生成 JSON に含めません。

Scrapbox のインポート画面は1ページ1万行未満を要求します。ソース全体をそのまま連結すると超えるため、配信用 JS では構文木から余分な整形・コメントを省いたコードを生成します。変数名や処理の最適化は行いません。CSSは結合した宣言と順序、JSは参照先以外の構文木が配信時に変わっていないことをテストします。読みやすい元コードと作者コメントはGitHubの `src/features/` に残します。

JavaScript はブラウザ標準の ES Modules を使います。追加のランタイムライブラリはありません。現在の規模では機能別モジュールのまま配信し、バンドルによるスコープの統合を避けています。[MDN: JavaScript modules](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Modules)

## CSS と JS の順序を維持する

機能一覧はカテゴリ別に表示しますが、実際の読み込み順は `config/features.json` の `defaults.styles` と `defaults.scripts` に明示します。

CSS は後に書いた宣言が前の宣言を上書きする場合があります。そのため、見た目に影響する並べ替え、セレクターの統合、`!important` の一括削除、cascade layer の導入は今回の整理に含めていません。セレクター・値・宣言順は回帰比較で確認します。[MDN: CSS cascade](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Cascade/Introduction)

JS も初期化の順序を維持します。動的 import を並列化したり、全機能を新しいライフサイクル管理下へ移したりする変更は行っていません。Script 内の AbortController や MutationObserver の扱いも維持しています。

グラフビューの CSS は Script が自身の `import.meta.url` を基準に読み込みます。これを全体 CSS に追加すると、CSS だけを使う人にも新たな装飾が適用されるため、従来の読み込み範囲を保っています。

CSS変数は色として等価でも文字列として読み取れます。`npm run format:css` は変数の値の表記を保ちながら整形します。ブラウザ比較ではCSS変数もそのまま照合し、大文字・小文字などの差も検出します。

## 設定と説明を同期する

`config/features.json` は、機能名・用途・使い方・有効状態・読み込み順の情報源です。生成処理が公開入口、機能一覧、各機能の README、読み込み順を更新します。

`npm run check` は生成物の更新漏れを検出します。説明だけ更新されて実際の設定が変わらない、またはその逆になる状態を防ぎます。変換表のような機能固有のデータは、その機能内の JS モジュールへ分離します。

## 元コードを追えるようにする

旧版・試作は `archive/scrapbox/` に分け、現行入口からは読み込みません。元から構文上の問題があった未使用コードも、修正せず保管しています。元の131ファイルと現在の保存先は `migration/paths.json` で対応付けています。

回帰テストでは、アーカイブ・テンプレートの元データ、CSSの宣言・順序・条件、JSの構文木、実行順、グラフの相対URLを確認します。比較元は初回コミットに固定します。補助モジュールへ移した宣言は [移動一覧](../migration/refactors.json) に記録し、元のスコープへ戻して比較します。参照できなくなった外側の変数や、読み込み時の新しい副作用も検査します。CSV・数式・置換・折りたたみ・色計算は入出力のテストも用意しています。

## 自動同期の範囲

GitHub Actions は `main` の検証が通った後だけ同期します。同期処理は `kame-layout:delivery` 以外を拒否し、既存ページに管理用マーカーがなければ上書きしません。変更前の配信ページをバックアップし、更新後はすべての `/api/code/` の本文とContent-Typeを照合します。既存ページを削除する処理はありません。

API はScrapboxの内部APIであり、認証はログインセッションを使います。これをGitHubへ保存して同期を有効化する操作は、コードの配置とは別に行います。詳細は [自動同期](auto-sync.md) を参照してください。
